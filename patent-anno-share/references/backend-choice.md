# 后端选型：WorkBuddy 云服务 vs 阿里云 OSS

## 一句话结论

**OSS 不能替代本 skill 的云服务。** OSS 是对象存储，不提供数据库和查询能力，
批注的「汇总、去重、按段筛选、多人冲突处理」都需要数据库，OSS 做不了。

但两者可以**组合**：OSS 存文件（PDF 原件、附图、导出的报告），云服务存批注。

## 能力对照

| 能力 | WorkBuddy 云服务 | 阿里云 OSS |
|---|---|---|
| 对象存储（存文件） | ✅ Storage 模块 | ✅ **本行是本行强项** |
| 结构化数据表 | ✅ PostgreSQL | ❌ 无（只能存 JSON 对象） |
| 条件查询 / 分页 / 排序 | ✅ PostgREST | ❌ 需自行遍历全部对象 |
| 按字段筛选（如按段号取批注） | ✅ 索引查询 | ❌ 只能列举后自己过滤 |
| 唯一约束 / 去重 | ✅ 数据库约束 | ❌ 无 |
| 并发写冲突处理 | ✅ upsert / 事务 | ❌ 后写覆盖，且无原子性 |
| 前端直传（免服务器） | ✅ publishableKey | ✅ AK + 临时 STS 令牌 |
| 跨域访问控制 | ✅ 按 Origin 精确匹配 | ✅ Bucket CORS 配置 |
| 免费额度 | 按平台策略 | 有免费额度，超出按量计费 |
| 需要自建后端吗 | ❌ 免运维 | ⚠️ 直传可免；要查询就必须自建服务 |

## 为什么"只用 OSS"做不成批注汇总

批注要回答的问题是：**「第 0054 段英文第 31–207 字这条批注，现在有几条备注、谁写的、最新是什么」**。

在 OSS 上只有两种存法，都有硬伤：

### 存法 A：一条批注一个对象

```
annotations/US20160183596A1/0054-en-31-207.json
```

要汇总全部批注，必须 `ListObjects` 拉全量键名，再逐个 `GetObject`。
1000 条批注 = 1001 次请求，且**无法按段号查询**（只能拉全量再过滤）。

### 存法 B：整个文档一个对象

```
annotations/US20160183596A1.json
```

每次保存要读全量 → 改一条 → 写回全量。两人同时保存 → **必然互相覆盖**，
后写的人把前一个人的批注全冲掉。OSS 没有乐观锁/事务来防这个。

数据库解决这两点各用一行：`where doc_id=? and para_no=?` 查，`upsert ... on conflict` 防覆盖。

## 若坚持用 OSS，需要补什么

必须自建一个中间服务（云函数 / ECS / 容器）来承担数据库职责：

```
浏览器 → 你的服务（鉴权、合并、去重）→ OSS（存 JSON）
```

这个服务的复杂度约等于自己写一个迷你数据库，且要处理并发、锁、索引。
**工作量大于直接用云服务**，除非你已有现成的服务端。

## 推荐的组合方案

```
WorkBuddy 云服务        阿里云 OSS
├─ annotations 表  ←→   ├─ 对比文件 PDF 原件
│  （批注结构化数据）     ├─ 附图 PNG
│                       ├─ 导出的批注汇总报告
└─ 提供查询/汇总/去重    └─ 提供大文件存储与 CDN 加速
```

具体做法：

1. **批注**继续用云服务数据库（本 skill 现有实现，不用改）
2. **大文件**（原始 PDF、专利附图）传 OSS，页面上用 OSS 直链展示
3. 若想让文件也走云服务，用 Storage 模块上传，拿签名 URL——这样单一后端更省心

## 如果确实要迁到阿里云

云服务的表结构和 API 都是**标准 PostgreSQL + PostgREST 风格**，迁移路径是清晰的：

| 组件 | 迁到阿里云对应服务 | 改动量 |
|---|---|---|
| PostgreSQL | RDS for PostgreSQL | 建表 SQL 直接可用 |
| PostgREST 风格 API | 需自建（Node/Python 包一层）或用阿里云 Data API | 要写一层接口 |
| 前端 SDK 调用 | 改成 `fetch` 打自己的 API | 改 `upsertMark`/`fetchMarks` 两处 |
| 静态页面托管 | OSS 静态网站托管 + CDN | 改部署方式 |

`upsertMark` / `fetchMarks` / `deleteMark` 三个函数是**唯一**依赖云服务 SDK 的地方，
换后端只需重写这三个，其余渲染和交互逻辑完全不用动。这是刻意做的隔离。

## 决策建议

| 你的情况 | 建议 |
|---|---|
| 只想尽快用起来 | 直接用 WorkBuddy 云服务，别折腾 |
| 公司合规要求数据在自己云上 | 迁阿里云 RDS + 自建一层 API |
| 只是要存 PDF/附图等大文件 | OSS 合适，批注仍留云服务 |
| 要长期对外服务大量用户 | 迁自建后端，注意批注表加索引与归档策略 |
